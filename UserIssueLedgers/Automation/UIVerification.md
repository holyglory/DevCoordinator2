| UIL-AUTOMATION-UI-VERIFICATION-001 | Conditional controls across general and specialized UI journeys | Verification repeatedly waited for controls already known to be absent because another exact journey owned them. | Declare one exact owner journey/state for each conditional control. Use realistic fixtures for owned absence, local presence, hidden controls, contradictions, missing/duplicate owners, and failed specialized journeys. |

Independently prove context recovery, ordered failure aggregation, and truthful unsafe-stop behavior without claiming complete coverage. |
| UIL-AUTOMATION-UI-VERIFICATION-003 | Browser and server readiness waits in UI verification | Fixed settle sleeps and repeated locator timeouts consumed hours even when the exact successful or absent state was already knowable. | Advance on an exact response, server readback, navigation, ready-or-error DOM state, or two-frame render boundary. Derive the expected default-fixture status and critical-rule set from its recorded metrics; give the unrelated metric a generous explicit threshold in each must-catch fixture; signal late-image readiness only after load and two animation frames; verify exit status agrees with the structured critical findings. |
