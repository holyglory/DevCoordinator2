# User Issue Ledger: UI / deployments

| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |
| --- | --- | --- | --- | --- |
| UIL-UI-DEPLOYMENTS-001 | Deployments collection, repository groups, deployment facts, and lifecycle controls at wide and narrow viewports | A seven-column desktop table left large dead areas at wide widths, then compressed names, endpoints, status, and actions into unreadable strips or pushed them off-screen as the viewport narrowed. | Present each repository and its deployments as a responsive operational section. Keep identity, state, endpoint, port, generation, recency, and every authorized lifecycle action visible; switch to labelled stacked facts before columns become cramped and never require document-level horizontal scrolling. | Exercise multiple repositories, long names and domains, managed and observed deployments, applying and degraded states, and every action at desktop, tablet, breakpoint-minus-one/at/plus-one, and several mobile widths. Verify all values and controls stay readable, associated, reachable, and free of clipping, overlap, and document overflow. |
| UIL-UI-DEPLOYMENTS-002 | Repository summaries on the Deployments dashboard | A global operational overview combined progress, tests, health, and decisions above the deployment list, obscuring which evidence belonged to which repository and forcing the owner to infer attribution. | Put the summary inside each repository section. Show only that repository's plan, progress, Codex usage, tests, health, latest decision, and deployments together; keep missing information explicitly unavailable and link Plan, Progress, Usage, and Decisions to the exact repository context. | Use repositories with deliberately different plan, progress, usage, test, health, and decision states, including missing and permission-limited evidence. Assert no value crosses repository boundaries, every repository-scoped link contains the matching repository identity, Tests and Health continuations retain visible attribution, and desktop, tablet, and mobile layouts preserve the association. |
| UIL-UI-DEPLOYMENTS-003 | Worker-density controls inside repository sections | The agent added an expander to every worker row, multiplying controls for a density choice that owners make about the worker collection as a whole. | Keep worker rows individually complete and remove their expanders. Provide one clearly labelled Workers disclosure per repository that hides or restores all worker rows together, independently of the repository-wide disclosure, with truthful count and expanded state. | Assert every worker row has no disclosure control; exercise the one repository-scoped Workers control by pointer, Enter, and Space; verify all rows hide or return together, sibling repositories remain unchanged, state survives same-session rerenders, repository collapse remains independent, lifecycle controls work after restoration, and wide/narrow layouts remain contained. |
| UIL-UI-DEPLOYMENTS-004 | Codex Usage summary inside each repository section | The dashboard treated an uninitialized repository-to-usage mapping as a final setup gap even when the authorized repository detail read could resolve existing measurements, leaving a false “not connected” summary beside a working Usage destination. | When the fast collection identifies only a pending mapping, show a truthful loading state and resolve that exact repository through the existing authorized detail path, then update only its Usage card in place. Do not trigger detail reads for real no-measurement, source-failure, or access states, and do not replace routine batched collection reads with per-repository scans. | Use divergent available-after-mapping, genuinely unobserved, source-failed, and denied fixtures. Assert pending mappings resolve sequentially without delaying the initial dashboard, the exact card gains measured totals without repainting the page or losing focus, other states and repositories do not trigger detail reads or change, and access/privacy plus collection-performance guarantees remain intact. |
