# User Issue Ledger: UI / tests

| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |
| --- | --- | --- | --- | --- |
| UIL-UI-TESTS-001 | Test-log reading in the Console | The log dialog first made people enter line or byte coordinates before showing output. Its initial correction replaced that form with a repeated **Load earlier output** button and still presented numbers and structured records as undifferentiated raw text. | Opening a selected log immediately shows readable output. When the reader reaches the earlier-output boundary, fetch the next bounded page automatically and preserve the exact reading position; never require a paging button or line/byte numbers. Keep search, likely-failure, and return-to-latest actions direct. Highlight at least numbers and common syntax/status tokens, and pretty-print valid JSON or JSON-lines deterministically while escaping every source byte as untrusted text. Exact coordinate retrieval remains an API and automation capability. | Exercise short, long, empty, active, failed, expired, multi-stream, numeric, JSON, JSONL, key/value, and hostile-markup logs through the rendered Console at wide and narrow sizes. Assert output loads on open and stream change, scrolling near the boundary follows only the returned cursor, progressive loading preserves position without duplicates or a paging button, search/failure pagination remains bounded, structured formatting never changes source identity or creates DOM from log markup, highlighting is accessible without color alone, and every visible control works. |
| UIL-UI-TESTS-002 | Current test runs and their visual-evidence actions in the Console | Stale run state and current-run-only evidence labels hid completed results and retained screenshots from earlier runs. | Refresh visible run state without moving focus, closing disclosures or dialogs, or duplicating requests. Distinguish current-run evidence from earlier retained screenshots using the actual count and run date; the earlier evidence action must open that exact run. Never imply that elapsed time creates screenshots or that earlier captures prove the latest run. | Exercise run transitions, nonvisual latest runs with retained earlier screenshots, missing or expired captures, refresh failure and recovery, navigation, open disclosures and dialogs, and denied access. Verify exact run ownership end to end, stable focus and scroll, and both themes at wide/narrow sizes. |
| UIL-UI-TESTS-003 | Tests hierarchy and shared Console presentation | A dense operational table exposed paths, byte counts, tier settings and administrative actions before the result people came to inspect. | Lead with one latest-results collection showing repository, test, result and readable duration. Reveal logs, check results, evidence provenance and technical details in context. Keep configuration secondary; use the approved shared light/dark visual language without a separate attention section. | Verify first-viewport hierarchy, expandable rows, settings and rerun dialogs, theme persistence, keyboard operation and narrow layouts; every enabled control must reach its stated result. |
